Proposal: element-level feedback for html-visualize

Anchor a comment to anything on the page — a word, a table row, a line of code, a diagram node — not just a run of text.

Why

Today a comment can anchor to a run of selected text, or to a whole block — nothing in between, and nothing visual. The moment the reviewed content contains a table, a code listing, or a diagram, precision falls off a cliff: you can select the text of a table row, but not say the row; you can say “the diagram”, but never the node.

The target model

The fix is one small, uniform idea: every comment carries a target, and a target has a kind. Four kinds cover the page:

kindanchors tocarried fields
quotea selected phrase — one word is enoughblockId · quote · quoteStart
blocka whole paragraph, list, table, or code blockblockId
elementone item inside a block — list item, table row, code lineblockId · selector · label
diagram-nodeone node in a rendered Mermaid diagramblockId · nodeId · label

What changes, what stays

  • Selecting text keeps working exactly as it does now — quote targets are unchanged, down to a single word.
  • Anything with its own identity becomes clickable: list items, table rows, code lines.
  • Mermaid nodes resolve to their source node id, so a comment on a node maps straight back to the diagram source text.
  • One payload shape for all four kinds — the server stays a dumb pipe; only the schema doc and app.js learn the new field.

Reading it back (app.js side)

// Normalise every incoming comment to one target shape.function normalizeTarget(c) { const t = c.target; if (t && t.kind === 'diagram-node') { return { kind: 'diagram-node', blockId: t.blockId, nodeId: t.nodeId, label: t.label }; } if (t && t.kind === 'element') { return { kind: 'element', blockId: t.blockId, selector: t.selector, label: t.label }; } // Legacy shape: quote/quoteStart live on the comment itself. if (c.quote) return { kind: 'quote', blockId: c.blockId, quote: c.quote, quoteStart: c.quoteStart }; return { kind: 'block', blockId: c.blockId };}

Open question

Whether the legacy comment shape (quote and quoteStart directly on the comment) should still be emitted for one release, or whether the schema can change in place — the only consumer is Claude reading the feedback file, so there is no third party to migrate.
